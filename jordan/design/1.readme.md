# Concert Ticket Booking System Design

## Problem Statement

Design a concert ticket booking system with the following requirements:

### Functional Requirements
1. **Ticket Limit**: The system has only 1,000 tickets. Do not exceed this limit.
2. **No Duplicate Seats**: Do not allow users to select duplicated zone and seat.

### Non-Functional Requirements
1. **High Concurrency**: Expected users are more than 1 million users at once.
2. **High Availability**: System availability must be more than 99%.

## Hints to Consider

### Key Challenges
- How will you prevent two users from booking the same seat at the exact same time?
- How will you ensure the 1,000 ticket limit is never exceeded?
- How will you handle 1+ million concurrent users?
- How will you achieve 99% availability?

### Think About
- What happens when a user selects a seat but doesn't complete payment?
- What if your database fails during peak traffic?
- What if payment processing takes too long?
- How will you handle network partitions?

### Components to Consider
- Load distribution
- Caching layers
- Database design
- Concurrency control mechanisms
- Scalability strategies
- Fault tolerance
